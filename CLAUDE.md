## Code Style
- Keep code elementary, shortest working solution possible.
- Hardcode solutions only after consulting to me.
- Delete dead code instead of commenting it out.
- Don't reformat lines you didn't change
- Attempt to keep code elementary and don't overcomplicate the structure / interactions

## Comments
- Comment only non-obvious code sections.
- One line maximum, no block comments, banners, or file headers.
- No docstrings.
- No TODOs or FIXMEs, that information should be stored elsewhere.

## Safety
- Never hardcode secrets, keys, or tokens.
- Don't hardcode a fix to a current problem for short term gains.

## Chat Output
- Answer first. No preamble, no "Great question", no recap of my request.
- Short sentences. Common words.
- Any software or complex coding terminology should be used sparingly when describing things
- Max 3 sentences per paragraph.
- Say "I don't know" when you don't know.

- Code should be well organized
