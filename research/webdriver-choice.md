# Choosing a browser-automation library for the scraper

Research date: 2026-09-03. All version/release/issue data below was pulled live from PyPI's JSON API, the GitHub REST API, and project READMEs/docs on this date; "latest release" and "last push" are as of that date.

## 1. Recommendation

**Use SeleniumBase, in CDP Mode (`sb_cdp.Chrome`).** It is the only candidate that ships a genuinely one-call synchronous "open URL, hand back HTML" API (`sb.activate_cdp_mode(url)` then `sb.get_html()`), explicitly supports Python 3.13 and Windows, is under active same-day development, is MIT-licensed, and has built-in helpers (`sb.solve_captcha()`, `sb.get_beautiful_soup()`) that line up with the beautifulsoup4 dependency already in this project. It clears Cloudflare's passive "Just a moment" JS challenge and has purpose-built helpers for the interactive Turnstile checkbox; it does not claim to clear Cloudflare Enterprise bot management.

This would be the wrong pick if: (a) headless operation is required for scale — SeleniumBase's own docs say UC/CDP stealth is detectable headless, so at "thousands of sites" you'd be running real (or virtually-displayed) browser windows, which is a real resource cost; or (b) a site sits behind Cloudflare Enterprise or a harder WAF (Akamai, DataDome, Kasada) — nothing evaluated here has a solid, verified claim of clearing those consistently, and you'd need to re-evaluate (nodriver scored best in the one independent benchmark found) or add a paid captcha-solving service.

## 3. Per-candidate notes

### SeleniumBase (UC Mode / CDP Mode)
- PyPI `seleniumbase` 4.53.6, uploaded 2026-09-02T21:13:05Z, `requires_python >= 3.10`, classifiers explicitly list 3.10 through 3.15. ([pypi.org/pypi/seleniumbase/json](https://pypi.org/pypi/seleniumbase/json), accessed 2026-09-03)
- GitHub repo `seleniumbase/SeleniumBase`: last push 2026-09-02T21:12:17Z, 12,978 stars, only 14 open issues, MIT license per the repo's license file. ([api.github.com/repos/seleniumbase/SeleniumBase](https://api.github.com/repos/seleniumbase/SeleniumBase), accessed 2026-09-03)
- README claims: UC Mode + CDP Mode "bypass Cloudflare's challenge page," and that the browser "passed" Sannysoft and BrowserScan bot-detection test suites. These are the project's own claims, not independently verified here. ([README.md](https://github.com/seleniumbase/SeleniumBase/blob/master/README.md), accessed 2026-09-03)
- Official docs list `sb.solve_captcha()`, `sb.click_captcha()`, `sb.gui_click_captcha()` for Turnstile-style challenges, but do **not** distinguish passive-JS vs. interactive-Turnstile vs. Enterprise — treat the "clears Turnstile" claim as scoped to the ordinary interactive checkbox, not Cloudflare's managed/Enterprise bot rules. ([help_docs/cdp_mode_methods.md](https://raw.githubusercontent.com/seleniumbase/SeleniumBase/master/help_docs/cdp_mode_methods.md), accessed 2026-09-03)
- Direct, load-bearing quote from the UC Mode doc: **"UC Mode is detectable in Headless Mode, so don't combine those options."** The recommended workaround is `xvfb=True`, which is a Linux virtual-display mechanism with no Windows equivalent — on Windows you need a real (can be minimized) window. ([help_docs/uc_mode.md](https://github.com/seleniumbase/SeleniumBase/blob/master/help_docs/uc_mode.md), accessed 2026-09-03)
- `sb.get_html()` / `sb.get_page_source()` and a built-in `sb.get_beautiful_soup()` exist directly on the CDP-mode object, which maps directly onto this project's beautifulsoup4 dependency. ([help_docs/cdp_mode_methods.md](https://raw.githubusercontent.com/seleniumbase/SeleniumBase/master/help_docs/cdp_mode_methods.md), accessed 2026-09-03)

### nodriver
- PyPI `nodriver` 0.50.3, uploaded 2026-05-13T13:57:51Z, `requires_python >= 3.9`, classifiers include 3.13 (they also list 3.7/3.8, likely stale metadata inconsistent with the stated floor — noting the discrepancy rather than resolving it). ([pypi.org/pypi/nodriver/json](https://pypi.org/pypi/nodriver/json), accessed 2026-09-03)
- GitHub repo `ultrafunkamsterdam/nodriver`: last push 2026-05-13T13:58:15Z, 4,718 stars, only 14 open issues, license file is full AGPL-3.0 text. ([raw LICENSE.txt](https://raw.githubusercontent.com/ultrafunkamsterdam/nodriver/main/LICENSE.txt), accessed 2026-09-03)
- The README states directly: **"This is the official successor of the Undetected-Chromedriver python package."** ([README.md](https://github.com/ultrafunkamsterdam/nodriver/blob/main/README.md), accessed 2026-09-03)
- The API is **fully async** — every call needs `await`, and the README itself notes the author had to write a custom event-loop runner because plain `asyncio.run` didn't work for them. This directly conflicts with the "sync preferred" constraint. ([README.md](https://github.com/ultrafunkamsterdam/nodriver/blob/main/README.md), accessed 2026-09-03)
- Built-in `tab.cf_verify()` exists for Cloudflare but requires `opencv-python` and only works in "non-expert" mode per the README — i.e., it is not a universal Enterprise-tier solver. ([README.md](https://github.com/ultrafunkamsterdam/nodriver/blob/main/README.md), accessed 2026-09-03)
- Governance note: a community fork, `zendriver` ([cdpdriver/zendriver](https://github.com/cdpdriver/zendriver), >1,200 stars per search results, not independently verified here), exists specifically because — per its own stated rationale — upstream nodriver bugfixes went unmerged and outside contributions were restricted. This is a maintenance-health signal worth weighing, sourced from search-result summaries rather than a page I fetched directly, so treat it as lower-confidence. (accessed 2026-09-03)
- Independent benchmark data: a self-published blog by Ian L. Paterson (CEO of an identity-security company, Plurilock; no apparent commercial stake in any of the tools tested) ran 7 tools against 31 targets between 2026-05-13 and 2026-08-15, and reported nodriver as the only tool with "28 OK / 0 blocked," ahead of Patchright, Camoufox, and vanilla/rebrowser-Playwright. This is one blog's self-reported methodology, not peer-reviewed or independently reproduced here — treat as suggestive, not conclusive. ([ianlpaterson.com benchmark](https://ianlpaterson.com/blog/anti-detect-browser-benchmark-patchright-nodriver-curl-cffi/), accessed 2026-09-03, data through 2026-08-15)

### Camoufox
- PyPI `camoufox` 0.5.5, uploaded 2026-08-18T01:22:59Z, `requires_python >=3.10,<4.0`, classifiers include 3.13, license MPL-2.0. ([pypi.org/pypi/camoufox/json](https://pypi.org/pypi/camoufox/json), accessed 2026-09-03)
- GitHub repo `daijro/camoufox`: last push 2026-09-02T17:20:37Z, 11,647 stars, 109 open issues (notably higher than the other actively-maintained candidates), MPL-2.0 license. ([api.github.com/repos/daijro/camoufox](https://api.github.com/repos/daijro/camoufox), accessed 2026-09-03)
- It is a Firefox fork with C++-level property spoofing, not a Chromium tool, wrapped to expose a Playwright-compatible sync/async API (`camoufox.sync_api`, `camoufox.async_api`). ([README.md](https://github.com/daijro/camoufox), accessed 2026-09-03)
- Direct quote, maintainer's own candor about the arms race: **"Camoufox has gone down in performance due to the base Firefox version and newly discovered fingerprint inconsistencies."** This is the project's own admission, not a third-party criticism. ([README.md](https://github.com/daijro/camoufox), accessed 2026-09-03)
- Headless claim with an explicit caveat: "Camoufox patches Firefox's headless mode to appear the same as if it were running in a normal window," but the README also tells users to fall back to a virtual display "if headless mode ever leaks" — i.e., headless stealth is not guaranteed. ([README.md](https://github.com/daijro/camoufox), accessed 2026-09-03)
- Windows nuance: this applies to *building* Camoufox from source — the README says plainly, **"Camoufox's build system is designed to be used in Linux. WSL will not work!"** Running the pip-installed package with prebuilt binaries is cross-platform (Windows/macOS/Linux); only compiling patches yourself needs Linux. ([README.md](https://github.com/daijro/camoufox), accessed 2026-09-03)
- Cloudflare Turnstile specifically looks fragile in practice: issue #574, opened 2026-04-18, documents Turnstile silently failing inside Docker across three Camoufox versions and was closed as a duplicate of an older report (#311); issue #584, a feature request for a built-in "Cloudflare Turnstile and WAF solver," was closed as not planned. ([issue #574](https://github.com/daijro/camoufox/issues/574), [issue #584](https://github.com/daijro/camoufox/issues/584), both accessed 2026-09-03)

### patchright
- PyPI `patchright` 1.62.3, uploaded 2026-09-02T22:11:54Z, `requires_python >=3.10`, classifiers include 3.13. Its own project metadata points at Playwright's `v1.62.0` source tree, showing it tracks upstream Playwright releases within days. ([pypi.org/pypi/patchright/json](https://pypi.org/pypi/patchright/json), accessed 2026-09-03)
- GitHub repo `Kaliiiiiiiiii-Vinyzu/patchright-python`: last push 2026-08-29T14:29:17Z, 1,495 stars, only 2 open issues, Apache-2.0. ([api.github.com/repos/Kaliiiiiiiiii-Vinyzu/patchright-python](https://api.github.com/repos/Kaliiiiiiiiii-Vinyzu/patchright-python), accessed 2026-09-03)
- README describes concrete, named patches: closes the CDP `Runtime.enable` leak by evaluating JS in isolated contexts instead, disables the Console API, strips `--enable-automation`-style flags and adds `--disable-blink-features=AutomationControlled`, and allows interacting with closed shadow roots. It self-describes as "currently is considered undetectable" and lists Cloudflare, Kasada, Akamai, Datadome, and Fingerprint.com as bypassed — this is the project's own claim, unverified independently here. ([README.md](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright-python), accessed 2026-09-03)
- Corroborating third-party evidence that vanilla Playwright needs this: `microsoft/playwright` issue #34025, opened 2024-12-15, reports Playwright (all three engines) being trivially detected via the same CDP leak that patchright patches, and it has no visible maintainer commitment to fix it in the thread as fetched. ([issue #34025](https://github.com/microsoft/playwright/issues/34025), accessed 2026-09-03)
- Real-world adoption signal: `openclaw/openclaw` issue #52190, opened 2026-03-22, requests patchright as a swappable backend specifically because the maintainers' own `playwright-core`-based tool gets "detected and blocked by Cloudflare and similar bot-detection systems." ([issue #52190](https://github.com/openclaw/openclaw/issues/52190), accessed 2026-09-03)
- No built-in Turnstile-click helper was found in the README — unlike SeleniumBase, you'd write that logic yourself, which cuts against the "shortest working solution" goal.

## 4. Minimal code sketch for the recommendation

Using SeleniumBase's CDP Mode, a synchronous "give me settled HTML" helper is a handful of lines:

```python
from seleniumbase import sb_cdp

def get_html(url: str) -> str:
    sb = sb_cdp.Chrome(url)
    sb.sleep(2)  # let JS render / Cloudflare's passive check clear
    if sb.is_element_visible('[name="cf-turnstile-response"]'):
        sb.solve_captcha()
    html = sb.get_html()
    sb.quit()
    return html
```

`sb.solve_captcha()` is CDP Mode's own helper and needs no selector — the manual `is_element_visible` check above is only there to skip calling it on pages with no challenge. Run headed (or with `xvfb=True` on Linux later) — CDP Mode's own docs say it is detectable when combined with headless.

## 5. Open questions / what I could not verify

- **Enterprise Cloudflare bot management.** No candidate here has a solid, verifiable claim of consistently clearing Cloudflare Enterprise-tier managed challenges. All Cloudflare-defeat claims found (SeleniumBase, patchright, nodriver, undetected-chromedriver) are either the project's own marketing language or scoped to the ordinary JS-challenge/Turnstile tiers. If any of the 5 pilot sites use Enterprise bot management, none of these tools is confirmed to work and this needs to be tested empirically against the actual sites.
- **nodriver on Windows.** I could not find an explicit statement of Windows support in nodriver's README or docs, nor a confirmed Windows-blocking issue — this is an absence of evidence, not evidence of absence.
- **zendriver's actual maintenance quality** — I relied on search-result summaries rather than fetching its README/repo directly; if nodriver's async-only API and governance concerns become a blocker, zendriver deserves its own direct look before being ruled in or out.
- **The ianlpaterson.com benchmark's methodology** (target list, what "OK" vs "blocked" precisely measures, whether SeleniumBase was tested at all — it wasn't in the tool list found) is not fully transparent from what I fetched; treat its numbers as directional, not authoritative.
- **Undetected-chromedriver's exact current Cloudflare failure rate** — the community reports cited (discussion #1387, issue #824) came from search-result snippets, not pages I fetched and read directly; I'm confident in the staleness signals (release date, push date, disabled issue tracker) but less confident in the precise current failure mode.
- I did not test any of these tools against the actual pilot sites (pgamediacenter.com, fhlb.com, nycbar.org, sc.com, owens.house.gov) — this research is about the tooling landscape, not a confirmation that SeleniumBase clears those five specific sites.
